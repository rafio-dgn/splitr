# `REQ-D.5`: an unanticipated schema change, `line_item.raw_text`

**Date:** 2026-09-24 · **Migration:** `drizzle/0001_line_item_raw_text.sql`

## Why it wasn't planned

`REQ-D.1`'s schema gave `line_item` one text column, `description`. Nobody
planned for a second one until evidence forced it:

1. **C.4 (2026-09-23):** the 8B model categorised receipt *shorthand*
   correctly **2/10** times ("KNG PRWN PHAD" → `drinks`).
2. **D.6 (2026-09-24):** Raffaele chose to keep each line **both as printed
   and in plain English** (ADR-0021 §2). The printed text is the paper's
   truth, and the expanded text is what categorisation and search read.
   One column can't hold both.

## The change

```sql
ALTER TABLE `line_item` ADD `raw_text` text;
```

Generated by `drizzle-kit generate --name line_item_raw_text` from a one-field
edit to `src/db/schema.ts`. It's nullable, because an item typed by hand has no
printed original.

## The criteria

| Criterion | Evidence |
|---|---|
| A column added after the schema was settled | `raw_text`, added after `REQ-D.1`'s `0000_initial_schema.sql` was applied and in use |
| A new migration generated **and applied** | `0001_line_item_raw_text.sql`, applied `--local` and `--remote`. Both databases' `d1_migrations` list `0000` then `0001`, and `pragma_table_info('line_item')` shows `raw_text` |
| Every affected code path updated | The schema (`rawText`); the write (`addExpense` inserts `raw_text` in the same batch); the validation (`lineItems[].rawText` in `addExpenseFields`); the read (`listLineItems`); the display (the expense page shows "Printed as …") |
| **The original migration is not edited** | `git diff drizzle/0000_initial_schema.sql` is empty. Only `drizzle/meta/_journal.json` gained an entry, which is Drizzle's own record |

Verified end to end in production: a read receipt stored
`raw_text = "0857 INDO CAFE COFFEE MIX 3IN"` beside
`description = "Indocafe Coffeemix 3 in 1"`.
